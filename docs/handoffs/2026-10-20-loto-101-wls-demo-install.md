# LOTO 101 for WLS Demo: manual install

Puts the LOTO 101 course live for the **WLS Demo** tenant on production, by
hand, in two steps: upload its media through the Supabase dashboard, then
paste one SQL file into the SQL editor. Together they do what
`import_seed_module`, `approve_media` and steps 4 and 5 of
`scripts/strike-demo-wls.sh` would do. Nothing changes for any other tenant.

The SQL file is `docs/handoffs/2026-10-20-loto-101-wls-demo-install.sql`,
generated by `scripts/strike-seed-sql.mjs`. Regenerate it with:

```bash
node scripts/strike-seed-sql.mjs --seed services/learning-studio/seed/loto-101 \
  --tenant ddddbce8-c7ab-4855-8bcd-821d080617ee --approver <reviewer email>
```

## 1. Upload the 25 media files

The course's images, narration and captions live in
`services/learning-studio/seed/loto-101/` (every file there except
`module.json` and `media.json`; 3 MB in total).

1. Open the Supabase dashboard → project `zwtnpyjifbdytlektxlc` → **Storage**
   → bucket **strike-media**.
2. Create this folder path, one level at a time with **Create folder**:
   `ddddbce8-c7ab-4855-8bcd-821d080617ee` → `loto-101` → `v1`.
3. Inside `v1`, press **Upload files** and select all 25 files:
   - `scene-01-why.jpg` … `scene-08-restart.jpg` (8 images)
   - `hotspot-isolation.jpg`
   - `s1-why.mp3` … `s8-restart.mp3` (8 narration tracks)
   - `s1-why.vtt` … `s8-restart.vtt` (8 caption files)

The names must stay exactly as they are; the SQL refuses to run until all 25
are present at `ddddbce8-c7ab-4855-8bcd-821d080617ee/loto-101/v1/<name>`.

## 2. Run the SQL

1. Open the `.sql` file on GitHub, press **Raw**, and copy everything.
2. Supabase dashboard → **SQL Editor** → new query → paste → **Run**.
3. The result pane shows a notice like
   `Installed loto-101-control-hazardous-energy for tenant … (10 questions)`.

The script is all-or-nothing. If it stops with a message, nothing was
changed: fix the cause (usually a missing upload) and run it again. Running
it a second time after success is refused, so it cannot create duplicates.

What it writes: the module and its published version (with every image and
narration marked as reviewed by the approver named in the file), the
10-question knowledge check, WLS Demo's STRIKE settings row if missing, and a
training requirement that gates WLS Demo's **hot-work permits** on this
course. Delete the last `insert` in the file before running if you don't want
the gate yet.

## 3. See it

Sign in to the app as a WLS Demo user and open

```
/strike/loto-101-control-hazardous-energy
```

To see the permit flow from the screenshots, start a hot-work permit in WLS
Demo: the training panel lists each worker's status and offers **Train now**,
which needs `STRIKE_KIOSK_SECRET` set on Vercel.
